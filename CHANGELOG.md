# Changelog

## Unreleased
- Scientific verification upgrade: accepted-time accounting and attempt telemetry (retry_policy legacy_model_changing/dt_only, drive_time_mode legacy_step_index/accepted_time), a separate synthetic wave-memory channel benchmark, a scripted verification protocol with smoke/full configs and committed smoke evidence, and a CI smoke benchmark job.
- Pairwise collision guard ADOPTED as a real guard (default `min_pairwise_divergence` 0.10; pass `None` to disable). Retry variants are judged against the FULL-step candidate's minimum divergence, not their own, so a smaller-dt retry cannot launder a collided step past the guard; `run()` also checks the guard against the INITIAL state, so a run that starts collided is caught at step 0. Measured: catches fidelity ≥0.95 collisions at step 0 and ≥0.90 within the run, zero false positives on the stock run (12 steps / 7 accepted, seed 42, unchanged) and across 5 seeds. The offset sweep as previously constructed (three identical cells) is now refused at step 0, because its initial condition is itself a collision; it is re-runnable from a near-identical start (0.85), which reproduces the uniform-multiplier results. 14 pairwise-guard tests (was 10; the 4 new ones pin the margin condition below).
- Pairwise-guard margin condition (default `min_pairwise_margin` 0.05; CLI `--pairwise-margin`). The guard fires only when the collapse is pair-specific: minimum divergence below the threshold AND the mean divergence still more than 0.05 above the minimum. This resolves the guard-vs-exact long-horizon interaction: no single threshold could both catch sharp collisions and let the exact-mode global synchronisation run — at 0.05 the exact control still died at ~step 16 on the pairwise guard, at 0.02 it survived to ~step 27 but a 0.95 mismatched collision was only caught at step 26. With the margin, the exact control runs to the mean collapse at ~step 30 — identical to the guard opted out (35/30, 36/31, 33/28 on seeds 42/1/7) — while a planted 1.0 collision in exact mode is still caught at step 0 (margin 0.30 at step 1 vs ≤0.017 for the control when min < 0.10, a ~17x separation). One honest limit: a deliberately planted near-colliding SUBGROUP (the 0.85-start offset sweep in exact mode, margin 0.14–0.17) is still caught, because that subgroup genuinely is a collision — such a sweep needs the guard opted out (`None`). And an all-9-identical lattice has margin 0, so the pairwise step-0 check does not catch it; it latches in 5 steps with 0 accepted on `divergence_below_minimum`, as before adoption. The CLI now also exposes `--min-pairwise-divergence` (default 0.10) and `--pairwise-margin` (default 0.05).
- Purity floor recalibrated 0.05 → 0.02 (ACCEPTED 2026-11-09, Jean's maximise directive). Exact-mode purity settles at 1/32 = 0.03125, the theoretical minimum for a 32-dim state, so the old floor sat above the settled value and killed every exact run in 2–3 steps; 0.02 sits below the physical minimum, so exact runs survive (~30 accepted steps) and the guard never fires spuriously. Legacy min purity never drops below ~0.06 (8 seeds) and rises to ~0.9, so the recalibration does not change legacy runs. Under the recalibrated floor, exact mode first fails on `divergence_below_minimum` after ~30 accepted steps, as TP damping synchronises the whole lattice (the pairwise guard, with its margin condition, does not fire on this global synchronisation). The CLI `--purity-floor` default was still 0.05 and silently overrode the new default on plain CLI runs; it is now 0.02.
- Offset sweep RE-PINNED under the adopted guard (0.85 start, seeds 42/1/7, row and column). The exact-identical start is refused at step 0, so the sweep starts from three cells at fidelity 0.85 (init min-div ~0.14). Seed 42 row: uniform m=1.0/1.25/1.5/2.0/2.5/3.0 → 12/7, 12/7, 12/7, 11/6, 11/6, 10/5 (divergence above maximum at 3.0); ladder (1,1.5,3.0) → 8/3; phase (0,φ,φ) φ=0.01/0.02/0.05/0.10 → 12/7, 11/6, 9/4, 8/3. Under the 0.85 start the "stronger offset latches earlier" trend is a tendency, not a rule: phase is cleanly monotone on all 3 seeds, but multipliers are noisy — the seed-1 excursion persists (row m=2.0: 10/5 → m=2.5: 13/8 → m=3.0: 13/8) and seed 7 is hump-shaped (mild offsets run longer than control). At low offsets the trio's fidelity RISES (converging — matched clocks, dephasing contraction beats the offset; crossover around m=1.5–2.0). No row-vs-column systematic difference.
- Decomposed why a smaller-dt retry can move a pair apart (0.95 pair: full step converges, dt x0.5 retry diverges). The per-step fidelity change is a competition between the Euler unitary stage, which diverges the pair and shrinks only ~1.4x from full to half dt, and the dephasing contraction, which converges it and shrinks ~4x per halving (roughly dt²); at full dt the contraction wins, at half dt and below the Euler leak wins. Interaction, calibrator, mirror and projection are all ≤0.0004 single-stage and do not drive the flip. See the README.
- Decomposed the Euler unitary divergence into rotation vs projection clipping (seed 42, 0.95 matched-clock pair). Rotation contributes EXACTLY zero (exact unitary alone: ΔF = 0.000000000 at every dt — matched Hamiltonians rotate both cells together). The raw Euler step, measured in the Hilbert–Schmidt metric (no PSD, so no clipping), diverges the pair by only −0.001754 / −0.000466 / −0.000118 at full / half / quarter dt — ~5x smaller than the fidelity-measured Euler+clip drop (−0.009500 / −0.006838 / −0.002662) and monotone in dt, with NO peak. The projection method flips the sign: the same raw Euler state through a shift projection gives +0.020984 / +0.003926 / −0.000002. Conclusion: the "Euler unitary divergence" as measured by fidelity-after-clip-projection is dominated by the projection + fidelity composition, not by the Euler step itself. The seed-42 dt≈0.04 peak is a feature of that composition for a given (H, ρ) pair, not of the raw Euler step: it appears in ~half the cases at dt≈0.035–0.045 (seed 42 peaks at 0.036, −0.011693; seeds 1 and 7 show no peak; one pair reverses). See the README.
- Exact-mode offset sweep under the recalibrated floor: flat — every offset (uniform 1.5/2.0/3.0, phase 0.05) latches at 33 steps / 28 accepted via `divergence_below_minimum`, vs 37/32 for the control; the subgroup desynchronisation is TRANSIENT in exact mode (three-cell fidelity dips to ~0.81–0.93 then climbs back to ~0.97 as TP damping re-synchronises), unlike legacy mode where it falls monotonically. Exact-mode mismatched-clock collisions likewise dip (~0.83–0.86 at step ~5) then re-converge to ~0.97 — they do not reach the random floor, correcting the short-horizon conclusion.

## Unreleased (earlier)

- Added an opt-in Crystallize injection engine, `membrane_arena_3x3/crystallize_injection.py` (SYNTHETIC classical software). `MembraneArena3x3WithInjection` tries up to 3 variant proposals (smaller `dt`, softened mirror) on a rejected step, validates them with the unmodified `_validate`, and keeps a calibration ledger (Brier score, `100 (1 - 4 Brier)` points, 0.8 cost per variant). It uses its own seeded random stream, `max_attempts=0` is identical to stock, and the stock engine, guards, thresholds, breaker and CLI are unchanged.
- It does not cure the arena: in the measured sweep (seeds 42, 0, 1, 2, 3) every injected run still latched the breaker, after 9 to 12 steps instead of 8 or 9. See the README section "Crystallize injection (opt-in)" and `docs/injection_results.md`.
- Renamed the injection settings to `first_commit`, `first_factor` and `mirror_variant`; the default commit is now 0.35 (it was 0.75 earlier in this unreleased PR). The commit changes only the ledger, so the dynamics are unchanged. A variant step factor is capped below 1.
- Added `InjectionConfig(adaptive=True)` (default off): the first commit of each event is the smoothed pass rate `(passes + 4 * first_commit) / (events + 4)`. It affects only the ledger, never acceptance, guards, thresholds or the breaker. The summary has `adaptive_pass_rate` (None when off).
- Measured here (SYNTHETIC, one machine): fixed 0.35 is right near the stock pass rate (0.31 over 36 events) and wrong in the evolved-genome regime (about 0.9 pass rate), where an adaptive commit scores positive and ends near 0.87 to 0.91. 0.35 is a stock-regime default only. The injection does not cure the breaker. The phase-damping experiment and evolution fitness figures from the design note are not reproduced here.
- Added `scripts/injection_sweep.py` and 23 tests (the supplied contract tests, including the adaptive ones, plus added properties). 86 tests in total.
