## Unreleased (earlier)

- Added an opt-in Crystallize injection engine, `membrane_arena_3x3/crystallize_injection.py` (SYNTHETIC classical software). `MembraneArena3x3WithInjection` tries up to 3 variant proposals (smaller `dt`, softened mirror) on a rejected step, validates them with the unmodified `_validate`, and keeps a calibration ledger (Brier score, `100 (1 - 4 Brier)` points, 0.8 cost per variant). It uses its own random stream, `default_rng(seed + 10000007)`, `max_attempts=0` is identical to stock, and the stock engine, guards, thresholds, breaker and CLI are unchanged.
- It does not cure the arena: in the measured sweep (seeds 42, 0, 1, 2, 3) every injected run still latched the breaker, after 10 or 11 steps instead of 8 or 9. See the README section "Crystallize injection (opt-in)" and `docs/injection_results.md`.
- Renamed the injection settings to `first_commit`, `first_factor` and `mirror_variant`; the default commit is now 0.35 (it was 0.75 earlier in this unreleased PR). The commit changes only the ledger, so the dynamics are unchanged. A variant step factor is capped below 1.
- Added `InjectionConfig(adaptive=True)` (default off): the first commit of each event is the smoothed pass rate `(passes + 4 * first_commit) / (events + 4)`. It affects only the ledger, never acceptance, guards, thresholds or the breaker. The summary has `adaptive_pass_rate` (None when off).
- Measured here (SYNTHETIC, one machine): fixed 0.35 is right near the stock pass rate (0.31 over 36 events) and wrong in the evolved-genome regime (about 0.9 pass rate), where an adaptive commit scores positive and ends near 0.87 to 0.92. 0.35 is a stock-regime default only. The injection does not cure the breaker. The phase-damping experiment and evolution fitness figures from the design note are not reproduced here.
- Scoring and RNG aligned with the author's original module: exactly two forecasts are scored per event (`0.5 points(first commit) + 0.5 points(last commit) - 0.8 per variant tried`, not every variant), and the jitter is one `uniform(0.8, 1.2)` draw per attempt from `default_rng(seed + 10000007)` with `factor = min(factor * jitter, 0.99)`. Events now carry `calibration_first` and `calibration_revised`; attempts no longer carry per-variant points. The setting `rng_salt` became `seed_offset` (10_000_007). With the old scoring and stream the one-step differences from the notes on seeds 1 and 2 and the 3x to 6x score gap appeared; with this alignment the default-commit-0.75 table matches the notes (see the README).
- Fixed commit 0.35 now totals +68.0 and 0.75 totals -1215.0 over the five stock seeds; the numbers in this section are the re-measured ones.
- Multi-seed measurement: `scripts/injection_multiseed.py` (seeds 0 to 49, default and dt-only settings, four commit policies, both scorings, mean with 95% bootstrap intervals, breaker counts, paired differences against the stock engine) with its section and "Honest limits" in `docs/injection_results.md`. A fixed 0.35 commit does not score reliably positive on more seeds (mean -5.0 per run, interval includes zero, on seeds 0 to 49).

All 12 confirmatory decisions are unchanged. `docs/PREREGISTRATION-injection.md` has a dated Amendment A1 (the original text is untouched); which ledger scoring is primary is recorded as pending the author's confirmation.

## 0.1.0 (unreleased)

- First version: a 3x3 lattice of 32-dimensional density-matrix cells, a read-only Yang Observer, a bounded Yin Calibrator with an optional sinusoid, transactional all-or-nothing updates, a circuit breaker and a command-line entry point. Started from a pasted specification and code, committed unchanged first.
- Changes to the pasted code: the `Generator` type annotation in `core.py` named a class that does not exist (`np.Generator`); the observer now works on read-only views; calibration actions log the lattice parameters in effect instead of zeros; the summary of a zero-step run has the full shape (the CLI raised `KeyError`); `run()` no longer resets the step counter while keeping the logs; `EngineConfig` validates its settings and rejects a sinusoid at or above the sampling limit; invalid CLI settings are usage errors; the `--quiet` help text is accurate; docstrings that misdescribed dephasing, coherence, the stability score and the calibrator were corrected.
- Not changed, documented under "Known limits" in the README: the dynamics, the guard thresholds and the default parameters. The default settings latch the breaker after about 8 steps.
- AGPL-3.0-only with the full license text, CITATION.cff, .zenodo.json.
- 63 tests; CI on Python 3.10 to 3.13.
